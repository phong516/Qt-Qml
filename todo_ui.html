Architectural Diagram (Modular Todo App)

This diagram outlines the new modular structure of the Todo Application. As tasks related to each component are completed, their status will be reflected here.

classDiagram
    class Main {
        +TodoModel todoModel
        +TodoListView todoListView
        +TodoInput todoInput
        +TodoCount countSection
    }

    class TodoModel {
        +int doneCount
        +int todoCount
        +int totalCount
        +string filter
        +addTask(desc)
        +removeTask(uuid)
        +setDone(uuid, done)
        +setFilter(criteria)
    }

    class TodoListView {
        +model todoModel
        +delegate TodoDelegate
    }

    class TodoDelegate {
        +string desc
        +bool done
        +string uuid
        +signal deleteRequested(uuid)
        +signal checkedChanged(uuid, done)
    }

    class TodoInput {
        +signal taskSubmitted(text)
    }

    class TodoCount {
        +int doneCount
        +int totalCount
        +int todoCount
        +string filter
        +signal filterChanged
    }

    class Model {
        <>
        TodoModel
    }

    class UI {
        <>
        TodoListView
        TodoDelegate
        TodoInput
        TodoCount
    }

    Main *-- TodoModel : uses
    Main *-- TodoListView : uses
    Main *-- TodoInput : uses
    Main *-- TodoCount : uses
    TodoListView *-- TodoDelegate : delegates
    TodoInput ..> Main : emits signal
    TodoDelegate ..> TodoModel : interacts via model
    TodoCount ..> TodoModel : reads counts
    TodoModel -- Model : defined in
    TodoListView -- UI : defined in
    TodoDelegate -- UI : defined in
    TodoInput -- UI : defined in
    TodoCount -- UI : defined in

Task 006 — C++ Backend Integration

  • Status: Completed
  • Score: C++ Architecture: 9/10, QML-C++ Binding: 9/10, Model Implementation: 10/10, Proxy Pattern: 9/10
  • Goal: Integrate C++ TodoManager as backend model for QML
  • Learning Targets Achieved:
    • Exposed C++ QAbstractListModel to QML via QML_NAMED_ELEMENT
    • Used qt_add_qml_module for C++ plugin registration in Backend module
    • Replaced QML ListModel with C++ TodoModel + TodoFilter proxy
    • Understood QML-C++ data binding through context properties
  • Key Implementation Details:
    • TodoModel (C++) implements QAbstractListModel with role-based data access
    • TodoFilter (C++) extends QSortFilterProxyModel for filtering logic
    • TodoManager (C++) exposes counted properties and invokable methods to QML
    • main.cpp wires manager → model → filter → QML context property
    • QML ListView binds to manager.proxyModel (filtered C++ model)
    • Delegate accesses role names: uuid, desc, done from C++ model
  • Architecture Benefits:
    • Proxy pattern separates filtering from data — single model, multiple views possible
    • C++ model scales better than QML ListModel for 1000+ items
    • Role-based data access allows safe refactoring without breaking UI bindings
    • Context properties expose objects to QML root without module registration
